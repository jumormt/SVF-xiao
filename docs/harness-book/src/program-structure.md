# Program Structure

Question: what program did SVF actually load, and how do I find stable names
and source locations for later queries?

Fixture: `/tmp/demo.ll` compiled from `demo.c`.

## 1. Start With Shape, Not Assumptions

```bash
Release-build/bin/svf-harness --oneshot summary /tmp/demo.ll
```

Representative output:

```json
{"functions":9,"icfg_nodes":93,"pag_nodes":183,"svfg_nodes":223}
```

The source has only a few C functions, but the module also contains external
declarations and compiler-lowered intrinsics. The graph counts tell you the
analysis state is non-empty and roughly the expected size.

## 2. Resolve Function Names

```bash
Release-build/bin/svf-harness --oneshot functions \
  --params '{"pattern":"make_buf|fill|use_after_free|malloc|free"}' /tmp/demo.ll
```

Representative output:

```json
{
  "functions": [
    {"name":"fill","is_decl":false,"loc":{"file":".../demo.c","line":5}},
    {"name":"free","is_decl":true,"loc":{"file":"","line":0}},
    {"name":"make_buf","is_decl":false,"loc":{"file":".../demo.c","line":4}},
    {"name":"malloc","is_decl":true,"loc":{"file":"","line":0}},
    {"name":"use_after_free","is_decl":false,"loc":{"file":".../demo.c","line":6}}
  ],
  "total": 5,
  "truncated": false
}
```

Use exact names from this result in later `callers`, `callees`, and `cfg`
queries. Do not guess mangled C++ names or compiler intrinsic names.

## 3. Inspect The Contract

```bash
Release-build/bin/svf-harness --oneshot schema /tmp/demo.ll > /tmp/schema.json
python3 - <<'PY'
import json
j = json.load(open("/tmp/schema.json"))
print("methods:", len(j["methods"]))
print("first method:", j["methods"][0]["name"])
PY
```

Use the schema when a command rejects parameters. It tells you which keys are
required and which anchor shapes each method accepts.

## 4. Record Analysis Configuration

```bash
Release-build/bin/svf-harness --oneshot analysis_config /tmp/demo.ll
```

Representative output:

```json
{
  "pointer_analysis": {"active": "andersen-wave-diff"},
  "svfg": {"mode": "full", "supported_modes": ["full", "ptr-only"]},
  "surfaces": [
    {"name": "dda", "status": "supported"},
    {"name": "cfl", "status": "supported"},
    {"name": "saber", "status": "supported"},
    {"name": "mta", "status": "supported"},
    {"name": "ae", "status": "supported"}
  ]
}
```

Save this next to any precision-sensitive result. If someone later reruns the
same query with a different SVFG mode or unavailable surface, the result may
not be comparable.

## Common Pitfalls

- Empty locations on `malloc` and `free` are normal because they are external
  declarations.
- `functions` uses regex search semantics. A broad pattern may match more than
  you intended.
- The schema is generated by the running binary. It wins over stale docs.
